Texture & Print

Grain, paper, halftone, riso, ink-wash and material texture - static texture craft for web and editorial work.

Textures: grain, noise, halftone, paper, material (vein opened Oct 18 2026)

Scope: static texture only. Texture is felt more than seen: it should survive squinting, not shout.

Noise fundamentals: Varun Vachhar, Noise in Creative Coding

Source: https://varun.ca/noise/ (2021). - Noise = SMOOTH randomness. math.random jumps nauseatingly; noise functions (Perlin, invented for Tron 1982; Simplex, his faster revision) return -1..1 values that vary organically - wave-like continuity. Output = mix of sin and random. Drive it with frequency (oscillation rate) and amplitude (output scale); map the -1..1 range to any target range by interpolation. - Dimensions = number of inputs: 1D wave motion (noise2D with y=0), 2D terrain/texture grids (x,y -> height or brightness), 3D vertex displacement (blobby distorted spheres), 4D = 3D + time for animated fireballs. - The 2D noise grid is the utilitarian workhorse: map brightness to a colour scale (plasma), run Marching Squares over it for contour rings (generative profile cards), or treat values as angles for a vector field; drop particles on the field and trace paths = flow fields (plotter art). - Particle systems: add noise-driven wiggle (x,y) over time for organic rain/snow/confetti instead of straight-line falls. - In shaders: glsl-noise + glslify; distance functions (patternZebra) quantize noise into rings; the same fragment becomes a Three.js ShaderMaterial driven by vertex position (3D planet surfaces). - For web UI grain: you do NOT need generative noise at runtime - bake or filter it. This article is the conceptual base: why noise looks organic where random looks wrong.

CSS-Tricks: Grainy Gradients, Jimmy Chion

Source: https://css-tricks.com/grainy-gradients/ (2021). The canonical web-grain recipe. - Core recipe: (1) SVG feTurbulence filter (type=fractalNoise, baseFrequency ~0.65, numOctaves 3, stitchTiles=stitch) rendered into a rect = the noise tile; (2) CSS background stacking the noise.svg URL with a gradient that ends transparent so noise shows through - layer order matters; (3) CSS filter contrast(170%) brightness(1000%) to push muddled grays out and fray the noise into grain; (4) optional overlay div with mix-blend-mode: multiply to unify colour. - Quirks: referencing the SVG filter by id from CSS does NOT work - use an external svg file URL or fully inline the SVG in the background data-URI. isolation: isolate on the wrapper or the blend leaks to the page background. feTurbulence noise is multicoloured; blend or filter if confetti is unwanted. - Use cases from the article: light/shadow grain (mix-blend-mode selective filtering), holographic foil (extreme brightness+contrast). - Comment-section wisdom: (a) subtle noise also fights BANDING in long smooth gradients - the dithering use, not just aesthetic; (b) perf caveat - heavy contrast/brightness filters can be expensive; (c) a MASK-based approach preserves colour range that the extreme brightness trick destroys. - Browser support: SVG-in-CSS-background universal in modern browsers; CSS filter effects no IE; Blink vs WebKit implement mix-blend-mode slightly differently - test, or reconcile with browser-targeted tweaks.

Sources: https://www.transparenttextures.com/, https://www.toptal.com/designers/subtlepatterns/. - Transparent Textures (Mike Hearn, "standing on the shoulders of Subtle Patterns"): pick a colour, pick a tile (3Px Tile, 45 Degree Fabric, Asfalt, Always Grey,...), grab the CSS. Tile size matters: tiny tiles (3px) read as grain; large tiles read as pattern.

Halftone: print history and mechanics, Wikipedia

Source: https://en.wikipedia.org/wiki/Halftone. - Definition: simulating continuous tone with dots that vary in SIZE (amplitude/pulse-width modulation) or SPACING (frequency modulation/stochastic screening) - one ink, one optical illusion: small dots read as smooth tone at distance. This is the same illusion web grain and dithering exploit; print just industrialized it. - History: Fox Talbot's 1852 patent ("photographic screens or veils"); first printed halftone photo Oct 30 1869 (Canadian Illustrated News); first full-tonal newspaper reproduction 1880 (NY Daily Graphic); Frederic Ives' commercial process 1881; Meisenbach's autotype 1882 (first commercial relief success). Regular in journals by early 1890s. - Screen ruling = lines per inch (lpi): screen printing 45-65, newsprint offset ~85, coated offset 85-185. Higher source resolution without matching screen ruling = posterization. Rule for web texture: tile frequency must match the detail level of what it textures - too fine reads as moire, too coarse reads as pattern. - Colour: repeat the halftone per CMYK ink; screens rotated to standardized angles so dots form rosettes instead of moire. Dots partially overlap - autotypical (part additive, part subtractive) mixing. SCREEN ANGLES AVOIDING MOIRE is the print ancestor of "don't tile two similar grids on a page". - Dot shapes: round (most common, good for skin tones; meet at 70% tonal value), elliptical (meet at 40%/60% - pattern risk), square (best detail, bad for skin; corners meet at 50%). Shape choice changes the tonal curve where dots merge - same lever as choosing dot vs line vs cross tiles on the web. - Digital halftoning (1970s-80s): electronic dot generators, imagesetters (Linotronic 1984), laser printers. Digital cells are pixel clusters that grow in jumps, so dithering algorithms often beat digital halftoning for tone quality. Inverse halftoning/descreening = reconstructing continuous tone from a scan - an ill-posed problem, relevant when reusing scanned print texture assets.

Dithering: Surma, Ditherpunk

Source: https://surma.dev/things/ditherpunk/ (2021). The definitive monochrome dithering survey, with runnable JS. - Dither = "intentionally applied noise to randomize quantization error". Quantization maps many values to few (256 greys to black+white); naive thresholding (brightness > 0.5) destroys mid-tones. Adding noise before the threshold statistically preserves brightness - pixels are "wrong" in proportion to how far they sit from the threshold. - GAMMA FIRST: canvas/ImageData are sRGB, and 0.5 sRGB is NOT perceptual mid-grey. Convert to linear RGB (gamma 2.4 formulas) before dithering or gradients dither far too bright. Any web texture algorithm that samples pixels needs this step. - Ordered dithering: instead of adding noise, vary the threshold per pixel via a precomputed threshold map - deterministic, parallelizable, GPU/shader-friendly (this is why Return of the Obra Dinn could run 2-colour 3D). Adding noise vs comparing against a threshold map are algebraically equivalent. - White noise threshold map: fast but clusters and voids (visible via squint or Gaussian blur) - detail loss where clusters land. - Bayer matrices: recursive 2^n+1 x 2^n+1 threshold grids (level 0 = 2x2 [[0,2],[3,1]]). Structured, repetitive look (the classic "Bayer texture"); biases images LIGHTER at low brightness (1/255 brightness still flips 1 in 4 pixels white) - invert the comparison to bias darker instead. Levels 1 and 3 most pleasing per Surma. Tiling maps match tileable textures: bake once, repeat. - Blue noise: high-frequency-weighted noise = no clusters/voids, even organic distribution, tiles seamlessly (generated on a torus via void-and-cluster, Ulichney). Best-looking static map; generation is expensive (~1 min per 64x64 tile in JS) but generation is OFFLINE - a baked blue-noise tile is as cheap as any image at runtime. - Error diffusion: sequential; quantize, measure the signed error, spread it to unvisited neighbours via a diffusion matrix. Simple 2D (50/50 right+below) creates line patterns; Floyd-Steinberg (1/16 * 7,3,5,1) kills most patterning but flat areas still look mechanical; Jarvis-Judice-Ninke (48-divisor, wider) smoother still; Atkinson (Apple/Mac classic; diffuses only 6/8 of the error = higher perceived contrast, punchier look); Riemersma (traverse a Hilbert curve, diffuse a weighted error history - organic like blue noise, simple to implement, but sequential so not GPU-able). - Aesthetic contrast trick (Obra Dinn): use blue noise for environments, Bayer for people/important objects - the difference in texture structure separates figure from ground with no colour change. Transferable to web: dithered image treatments can mark interactive/feature areas inside a uniformly textured page.

CSS halftone patterns: Michelle Barker, CSS IRL

Source: https://css-irl.info/css-halftone-patterns/ (2022), unpacking Ana Tudor's halftone demos into vanilla CSS. - Three ingredients: (1) repeating radial-gradient dot grid, (2) a mask carrying the image/pattern, (3) contrast filter as the secret weapon. - Dot grid: radial-gradient(circle at center, black 0.25rem, transparent 0) with small background-size; background-repeat: round avoids clipped dots. Angled/denser grid = two identical gradients offset by half the tile (position 0 0, 0.65rem 0.65rem). Custom properties (--dotSize, --bgSize, --stop1, --stop2) keep one control point. - Halftone sizing trick: give the radial gradient SOFT stops (fade from --stop1 to --stop2 instead of hard stops) so each dot is a blurred blob; apply mask-image (e.g. linear-gradient) to the dotted pseudo-element; then filter: contrast(50) on the PARENT snaps the blurred+masked blobs back into crisp dots whose SIZE follows mask opacity. Mask at 50% alpha -> mid-size dots; keep mask >= ~0.5 alpha to avoid empty zones. - Architecture: dots on::after (absolute, inset 0), mask on the same pseudo-element, contrast filter + solid background on the parent element. Contrast needs a solid background colour or nothing shows. - Colour: contrast distorts non-white parent backgrounds, so colour via mix-blend-mode instead: multiply renders white transparent (black dots over a coloured backdrop); screen keeps white, tints dots; invert filter flips for dark schemes: filter: contrast(50) invert(var(--invert, 0)). - Masks beyond gradients: radial/conic/repeating gradients, transparent PNGs, SVGs - the mask IS the image. (Ana Tudor has a separate demo halftoning real photos.) Limitation: dots or background must be black/white for the filter+blend math to stay clean.

Risograph: the machine behind riso-print aesthetics, Wikipedia

Source: https://en.wikipedia.org/wiki/Risograph. - What it is: Riso Kagaku's digital duplicator (Japan, 1980) - a mimeograph descendant. Thermal heads burn a master with microscopic holes; the master wraps a drum; soy-based ink is forced through the holes onto paper running flat under the drum. 150 pages/minute, economical from ~100 copies up to the offset threshold (~10k). Drum per colour; MZ series runs two colours per pass. - Why it looks the way it looks (the design takeaways): soy ink needs UNCOATED paper -> ink sits in the fibre, giving the soft, matte, slightly absorbed look; stencil-through-holes imaging gives a characteristic grain; spot colours (fluorescent pink, mint, etc.) because drums swap, not CMYK blending; and because each colour is a separate pass/drum, MISREGISTRATION is inherent - the slight offset between colour layers that designers now fake deliberately. - Context: made for schools/churches/campaigns (cheap short runs); adopted by artists in the 2010s for zines and comics - the democratic-DIY association is part of the aesthetic's meaning, not just its look.

CMYK CSS halftone: leanrada, Creating a halftone effect with CSS

Source: https://leanrada.com/notes/pure-css-halftone/ (2024). One-div halftone over real images. - Recipe: img inside a wrapper; wrapper gets filter: brightness(0.8) blur(3px) contrast(999) - brightness sets the threshold point, blur emulates ink surface tension, extreme contrast thresholds to pure black/white.::after overlay carries a blurry dot grid (radial-gradient(10px at center, black, white); background-size ~20px) with mix-blend-mode: screen. Screen lightens multiplicatively, so blurry dots shrink in light source areas and bleed together in dark ones - dot size tracks tone, the halftone illusion, before thresholding. - Colour version: add one dot layer each for C, M, Y (plus black), staggered positions; contrast(999) thresholds each RGB channel independently, so pure #0ff/#f0f/#ff0 layers behave like separate ink plates. Mix the layers with background-blend-mode: multiply to simulate subtractive ink mixing. - Gotchas documented: "colour is contagious" - screening a coloured source with the BLACK dot pattern tints the black dots; fix = separate-K: the black plate screens against a greyscale copy, CMY plates against the colour image. Staggering quality matters (halftone angles/moire, per). Not an accurate CMYK simulation (operations happen in RGB), but looks right in many cases; tweak brightness/saturation per source image. - vs css-irl: css-irl masks a dot grid to MAKE patterns; leanrada screens an actual IMAGE into halftone. Same levers (radial-gradient dots, blend modes, contrast), different goal. Both static, pure CSS.

Textures in web design strategy: Shakuro

Source: https://shakuro.com/blog/when-and-why-use-textures-for-web-design (2022). Agency-level design-strategy framing; light on craft, useful on placement and restraint rules. - Texture vs pattern: patterns are small algorithmically-repeatable tiles (lightweight, eye notices tiling but not distracted); textures are complex high-detail surfaces (photo-based, tiling seams hard to hide, sometimes a single non-repeating image). Choose per message: pattern for ambient rhythm, texture for material presence. - Why textures work: they replicate physical sensations - instant material associations (paper = editorial/craft, dirt/grunge = gym, water = pool, soft noise = neutral cozy). Emotional tie-in builds brand recall when the texture is distinctive and repeated. - Placement rules: textures guide attention by contrast - put them on titles, buttons, CTAs, headers, or as background separators INSTEAD of lines/boxes/colour-blocks; above-the-fold texture + readable headline pulls the scroll. (Matches the library's no-grey-lines direction: a texture shift can do a divider's job.) - Restraint rules: (1) less is more - only essential sections; (2) never sacrifice text readability - check contrast and colour-blindness; (3) one texture style per site - mixing noise, paper and grunge reads as indecision (users form an opinion in ~50ms); (4) fit the target audience's expectations; (5) photo-based textures are HEAVY - optimize aggressively, slow pages lose ~40% of engagement. - Library synthesis: this is the conservative baseline. The craft frontier is doing the same jobs with tiny generated tiles (feTurbulence, CSS gradients) instead of heavy photo textures - same felt-not-seen effect at ~0 page-weight cost.

feTurbulence reference + deep guide: MDN and Sara Soueidan/Codrops

Sources: https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feTurbulence, https://tympanus.net/codrops/2019/02/19/svg-filter-effects-creating-texture-with-feturbulence/ (Sara Soueidan, 2019). - MDN facts: feTurbulence renders Perlin turbulence into the filter region ("clouds, marble"); works in linearRGB by default (color-interpolation-filters switches to sRGB); baseline since July 2015; five attributes: type, baseFrequency, numOctaves, seed, stitchTiles. Example pairs it with feDisplacementMap to ripple a circle. - Parameter map (Soueidan's visual experiments): - baseFrequency: grain scale. 0.001 = huge cloud forms, 0.5+ = fine grain; "0.02-0.2 useful starting range for most textures" (Michael Mullany). TWO values give anisotropic x/y frequencies - 0.01 0.4 = horizontal streaks, the basis for brushed/liquid/wood effects. Changing it zooms the pattern around the top-left origin. - type: turbulence (default) = ripple lines, base for liquid textures; fractalNoise = cloudy smooth, base for gas/cloud/paper. Switching turbulence -> fractalNoise instantly dials any effect down. - numOctaves: detail layers. Default 1; diminishing returns past 5. Roughness = octaves (paper needed ~5). - seed: PRNG start point - same seed = noise continuous across adjacent rects; different seeds = same character, different arrangement (cheap variations of one texture). - stitchTiles: stitch = smooths tile seams for repeating backgrounds. Default noStitch shows discontinuities. - Distortion use: feTurbulence -> feDisplacementMap (scale = distortion intensity, x/yChannelSelector pick colour channels). Applies to HTML content via CSS filter: url(#noise), not just SVG. baseFrequency is animatable (GSAP setAttribute) - squiggly-text and button-distortion effects; but animated SVG filters are resource-hungry, keep to small areas, and unsupported browsers degrade gracefully (button just looks normal). - Rough paper recipe (Michael Mullany breakdown): feTurbulence fractalNoise baseFrequency 0.04 numOctaves 5 -> feDiffuseLighting lighting-color white surfaceScale 2 with feDistantLight azimuth 45 elevation 60. Mechanism: lighting filters use the ALPHA channel as a bump map (opaque = peaks, transparent = valleys); turbulence's noisy alpha = free Z-terrain; fractalNoise removes sharp creases; octaves add tooth; lower elevation = steeper contrast. Light types: feDiffuseLighting (sunlight/indirect) vs feSpecularLighting (reflective bounce); sources: feDistantLight (angle), fePointLight (xyz), feSpotLight (cone). - Practical synthesis for the library: bake the result to a static tile (screenshot/canvas export) for production - runtime filter cost paid once. Static grain rule intact: generate with motion-capable tools, ship static.

Paper texture backgrounds: Gradiently guide

Source: https://gradiently.design/guide/paper-texture-background (2026). - Convincing digital paper = THREE layers: tinted base colour + fine fibre/grain + slightly uneven light. Most fake paper overdoes the third (creases, stains, torn edges = clip art, dates fast). Real paper is never pure white. - Stock table (name the stock before designing): cotton rag #f6f1e7 (wedding/certificates), uncoated cream #f3ead8 (menus/journals), kraft #c8a57a (coffee/bakery), newsprint #e9e5dc (zines/editorial/protest), recycled grey #dcd8d0 (sustainable), washi #f4efe4 (tea/ceramics/spa). Ink: warm near-black #2b2420 (pure black looks digital on a tinted sheet); one accent e.g. stamp red #8a2b1f used ONCE per design. - Don'ts: heavy creases across text, coffee stains/burnt edges, torn borders, visible scanner-bed shadows, grey small text on cream. Do: fine tooth just visible at 100%, low-opacity fibres, gently uneven light, warm ink. - Placement: paper earns its keep where a printed object would naturally exist - invitations, menus, journals, quote cards, craft brands. Serifs sit at home on cream/cotton; clean sans on newsprint/recycled reads modern-industrial. Texture eats contrast: bump body text weight, check on phones. - CSS recipe: base = two radial-gradient light washes over the stock colour (e.g. #fbf7ef at 20% 15% and #e8dcc4 at 85% 90% over #f3ead8);::after fibre layer = inline data-URI SVG with feTurbulence fractalNoise baseFrequency 0.55 numOctaves 4 stitchTiles stitch + feColorMatrix saturate 0 (desaturates the rainbow noise to grey fibre), mix-blend-mode multiply, opacity 0.08. Multiply keeps the sheet warm; raise opacity for kraft. Lower baseFrequency than film grain = softer fibre.

Dithering in browsers and banding: Smerity

Source: https://smerity.com/articles/2013/dithering.html (2013). - Dithering = exploiting the eye's spatial mixing to fake colours outside the palette. SPATIAL dithering: red+blue checkerboard reads as purple (old games, GIFs). TEMPORAL dithering: alternate two colours fast enough and they average - used in hardware to make cheap panels look better (epilepsy warning on demos; requestAnimationFrame, not GIFs, for browser experiments). - Colour context: CSS colours are 24-bit (8 bits/channel) - 16M colours, and STILL banding happens: a soft gradient like #333 -> #666 spans only 51 steps per channel, and each step is a visible band. 8-bit depth is the root cause of web gradient banding. - (Cut section likely covered the fix - completed by + 343: add noise, or step the gradient.)

Mitigating CSS gradient banding: kuon.ch stepped gradients

Source: https://kuon.ch/post/2016-09-16-css-gradient/ (2016). - Problem: browsers render naive A->B gradients with visible banding (confirmed in Safari, Chrome, Firefox). - Fix: the "stepped gradient" - replace one long A->B interpolation with N short segments A->A1->A2...->B, each segment itself a tiny gradient. Bands shrink below visibility because no single segment spans enough steps to show a hard edge. SASS loop appends paired colour stops (fade-out($bg, 1/$i)) at increasing percentages, ~10 steps, with a small offset between paired stops. - When to use which anti-banding tool (library synthesis): (1) subtle noise overlay - recipe, best for hero/photo gradients, also adds craft texture; (2) stepped gradient - pure CSS, zero assets, best for utility gradients where grain is unwanted; (3) shorter gradient distance / higher-contrast endpoints - design-level fix, fewer steps to band; (4) avoid large smooth dark-range gradients on cheap panels entirely - banding is worst in dark greys.

Riso techniques as CSS: jonathanstephens.us/play/riso

Source: https://jonathanstephens.us/play/riso/. A recipe sheet translating riso print behaviour into CSS. - Halftone simulation: radial-gradient dots, dot size 1-4px, tile 8-20px. Variable density = two dot sizes at two tile sizes offset half a tile. Offset a second colour's dot grid by half a tile for autotypical-style mixing. - Moire DELIBERATELY: repeating-linear-gradient lines at 2-3 different angles (30/45/60 classics), 1px subtle / 3px bold. This is the one context where moire is the goal rather than the failure mode (contrast screen-angle rules). - Colour mixing: layers with position absolute + mix-blend-mode multiply; blue+yellow=green, red+blue=purple, red+yellow=orange. The multiply IS the ink. - Duotone photos: img with filter grayscale(100%) contrast(1.2-1.3), overlay div with multiply + colour gradient = vintage riso poster treatment. - When to use what: halftone = fill/tonal variation; moire = textile complexity; multiply mixing = palette maximization from few spot colours; duotone = photo treatments.

Retro text texture effects: Gradiently riso/double/trail

Source: https://gradiently.design/guide/retro-text-effect (2026). Three cheap-printing text treatments. - The three: RISO (two inks slightly out of register, multiplied where they overlap), DOUBLE (one crisp solid echo offset 5-8% of letter height - reads screen-print/sticker; too close looks like a mistake, push further than feels safe), TRAIL (4-8 stepped copies, colour-shifted = 70s title, fading = motion; even steps only). - Riso ink palette (screen approximations): fluorescent pink #ff48b0, medium blue #0078bf, yellow #ffe800, teal #00838a, bright red #f15060 on uncoated paper #f4efe6. Classic pairings: pink+blue (deep violet overlap = the detail that sells it), yellow+teal. - CSS recipes: double/trail = text-shadow stacks with em offsets (scales with font-size, real selectable text); riso = element +::after with content: attr(data-text), translate(0.04em, -0.03em), both multiply. CAVEATS: multiply vanishes on dark grounds (use double instead); some screen readers announce generated content twice. - Usage rules: heavy/simple or soft-70s-serif faces; headline only (2-5 words), details flat; colours from the existing palette; ONE effect per design ("riso plus trail plus outline is a costume").

Brushed metal: simurai (2011) + conic-gradient status

Sources: https://simurai.com/lab/2011/08/21/brushed-metal, https://css-tricks.com/brushed-metal-with-css-gradients/, https://developer.mozilla.org/en-US/docs/Web/CSS/gradient/conic-gradient. - The core trick (still current): a brushed texture = 3 repeating-linear-gradients with DIFFERENT periods layered, so the combined repeat is effectively invisible - prime-ish period layering defeats visible tiling (same principle as moire avoidance, inverted into a virtue). - Radial brushed metal (the pot-lid look) needed conical sweeps: in 2011 simurai faked them with ellipse gradients; conic-gradient is now Baseline since Nov 2020 - the radial version is straightforward today. - Material-texture principle for the library: metal = anisotropic streaks (one direction dominant) + low-contrast banding; the same anisotropy lever as feTurbulence's two-value baseFrequency. Wood = longer periods + warm palette; fabric = two perpendicular periods (weave). All are period-layered gradients + grain.

Film grain judgement: Gradiently grain guide

Source: https://gradiently.design/guide/textured-background (2026). The dosage guide for grain. - Grain's three practical jobs: hides banding, unifies mixed media (photo has grain, flat shape has none - one layer over both makes them cohere), adds a physical surface to flat colour ("reads as a material"). Matches on banding. - The distance test: just visible at 100%, invisible from arm's length on a phone. If anyone notices it first, halve it. - Dosage table (noise layer opacity, Overlay/Soft Light): website background 3-6% fine; social post 6-12% fine-medium (survives recompression); poster 10-18% medium; retro/film look 18-30% medium-coarse; video = animated grain. - Monochrome vs colour grain: mono keeps the palette exact (default; reads print/paper/riso); colour grain = analogue film, can shift brand colours. feTurbulence output is COLOURED by default - desaturate with feColorMatrix saturate 0 for mono. - Fine grain = expensive/modern; coarse = handmade/loud. Scale grain size to output size (bigger canvas, coarser allowance). - Recipe: mid-grey #808080 noise layer, Overlay or Soft Light blend, low opacity, on top of backgrounds but below crisp small type/logos (or over them for a printed feel). Export PNG/hi-JPEG - heavy compression smears grain into blotches. - Web recipe: fixed full-viewport SVG grain (fractalNoise baseFrequency 0.8, numOctaves 3, stitchTiles stitch, saturate 0), mix-blend-mode overlay, opacity 0.06, pointer-events none, aria-hidden.

CSS noise techniques measured: UDT guide

Source: https://ultimatedesigntools.com/blog/css-noise-textures-guide/ (2026). Notable: they rendered the techniques in Chromium and read the pixels back - measured, not vibes. - Measured comparison (over #0B0D17, base luma 14): inline SVG filter overlay 5% -> mean 17.2, SD 1.31, no visible repeat; 256px data-URI tile 5% -> mean 17.3, SD 1.19, repeats every 256px but seamless with stitchTiles; two repeating radial gradients (3px+4px) -> mean 23.5, SD 2.87, repeats EXACTLY every 12px (LCM) - eye catches the grid; it's a dot pattern, not noise. Conclusion: SVG routes win; the data-URI tile performs like inline without the markup. - feTurbulence fills all four channels with separate noise (full-opacity mean ~99 = coloured speckle, confirms); at 3-6% the tint is invisible; saturate-0 for strict grey. - EVERY OVERLAY LIFTS THE BACKGROUND (14 -> 17): check text contrast WITH the overlay on. On near-black backgrounds the lift is material (matches dark-needs-less). - Perf: live filter: url(#noise) on a fixed full-screen element computes per-pixel - GPU-hungry on mobile; a 256-512px pre-rendered tile (PNG or ~400-byte SVG data-URI) is decoded once and only composited. Limit live filters to hero zones; measure with the Performance panel before optimizing. - The grain overlay pattern: body::after, position fixed inset 0, background data-URI repeat, opacity 0.04, pointer-events none, z-index 9999. - Param map additions: baseFrequency 0.5-0.8 = fine background grain, <0.3 = clouds; white noise dots on dark bg, black dots on light bg; soft-light = gentler cross-theme blend. - Animated noise: steps keyframes on background position, 2-3% opacity, and ALWAYS prefers-reduced-motion gated.

Text over images: NN/g contrast rules

Source: https://www.nngroup.com/articles/text-over-images/ (Aurora Harley, 2015; reviewed Jan 2026). - Requirement: text over images needs 4.5:1 contrast (3:1 for large text - 18pt or 14pt bold). Legibility (distinguish characters) vs readability (process meaning) - low contrast forces users to strain or skip, and they usually skip. - Fixes that preserve the visual: darken the image or overlay a semi-transparent black gradient (the "floor fade"); blur the region behind the text (localizes the fix, lower photo areas tolerate it best); raise overlay-box opacity (NN/g's own REI redesign: 30% -> 50% black box passed 3:1); text shadow/outline as supplements. Position text near image edges where tone is even. - Worst-case rule: pick the fix against the WORST-case image and placement, not the average one - if a CMS can swap in a light photo, the technique must still pass. - Texture-specific synthesis (library): a grain layer at 3-6% barely moves contrast, but a COARSE pattern or busy texture behind text is a contrast hazard - treat texture behind text like an image background: measure with overlay on, keep texture out of small-text zones, prefer texture as section backdrop not text backdrop. Visual lessons below are and my analysis; designers' names come from captions I could see only for some (e.g. Sho Shibuya WEEK poster 2018, Shin Matsunaga PEACE 1986, Yu Miyazaki Kobo Abe posters 2009).</p> <h2>Why it matters for web</h2> <ul> <li>Type is part of the composition: Japanese typography is often custom-drawn per project because expressive Japanese typefaces are scarce, so letterforms integrate tightly with the other elements and the characters carry meaning AND visual expression. Web lesson: treat the headline as a drawn image, size/crop/overlap it, not a label.</li> <li>Text can run horizontally or vertically; Latin and Japanese mix freely. Variability of direction gives endless compositional options. Web lesson: vertical type (CSS writing-mode: vertical-rl or rotated labels) as one deliberate accent; mix a display script with a functional face.</li> <li>Energy and playfulness in compositions (Kamekura, Ikko Tanaka, Yokoo as named influences).</li> </ul> <h2>Composition lessons seen in the posters</h2> <ol> <li>One idea per poster, huge scale contrast: a massive logotype or glyph, then tiny dense information. (Morisawa series: heavy black katakana wordmark across the top, one generative grey line or gradient field filling the rest; WEEK poster: one circle-and-door glyph on flat grey.) Web: one giant type moment per section, everything else small and quiet. Matches his ONE rule.</li> <li>Generous empty field around a single subject (PEACE: blurred multicolour figure, widely letterspaced caps at the bottom edge; Earth "belonging to nobody": a lit globe centred in black). Web: black hero with one luminous object and a single line of widely tracked caps.</li> <li>Restricted palette: black/white/grey plus one saturated colour (red field with black brush kanji and a green bowl accent). Web: 60/30/10 with one accent.</li> <li>Type overlapped by the object: a product bottle cuts across giant letters (oltana SKIN MEDITATION); type crops at the edge; stacked repeating wordmark shrinking into the distance (Morisawa funnel). Web: scroll or cursor-driven overlap, cropped display type, repetition with scale change as motion.</li> <li>Information clusters: small, tightly set blocks of text placed asymmetrically beside the hero element, often with a thin rule or in a narrow column (exhibition posters). Web: metadata in small caps beside the hero, no boxes.</li> <li>Pattern and texture as type: letters built from patterned lines, halftone, line fields, or one repeated shape (Tomato Project). Web: SVG/canvas line-field backgrounds generated from the subject, not stock gradients.</li> <li>Diagonal or split compositions with narrow black bars and elegant serif Latin (N/Y poster). Web: one diagonal cut or split screen for contrast.</li> <li>Maximalist exceptions (anime, J-pop, tattoo-art, escape-game posters) are dense and loud: not for his minimal sites; useful only for entertainment/pop briefs.</li> </ol> <h2>Mapping to his rules</h2> <p>Pure black bg and white type work in the posters with dark backgrounds (tattoo-art series, globe poster). Avoid the stacked-cards look: Gurafiku posters never use boxes; hierarchy comes from scale and placement. Accent: black + one red is the most common restrained combination; check against his brand accent.</p> <h2>Next time</h2> <p>Pull Are.na-style moodboards by tag (gurafiku.tumblr.com/tagged/<tag>), study 3-5 posters per brief, write down: dominant element, scale ratio, palette, type treatment, information placement, then rebuild the STRUCTURE (not the artwork) in the page layout.</p> <div class="pagenav"><a href="motion.html">← Motion Craft</a><a href="case-studies.html">Case Studies →</a></div> </main> </div> </body> </html>
